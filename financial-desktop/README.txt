- 선택을 확인·수정하고 기록을 저장한 뒤, 상세에서 별도로 문서 검토를 시작합니다.
- 추론·제안 적용으로 검토/승인/업무 저장이 실행되지 않습니다. 수동 선택도 계속 가능합니다.
- 요청/후보/형식/선택 변경은 제안을 무효화합니다. 보류·오류면 수동 선택하세요.
- 모델·NumPy 2.3.5·Python은 이 ZIP에 포함됩니다. 외부 AI나 학습 기능은 없습니다.
- AI 입력·예측·열람/적용 이력은 stateDir.ai-previews에 별도 로컬 보관합니다.
- 원문과 후보 메타데이터만 모델 입력이며 문서 본문과 수동 정답은 입력하지 않습니다.

DIANA PC 금융 문서 검토 · Windows x64 휴대용 실행기

기록에서 로컬 문서 검토 (0.3.3)
- ‘요청 기록’ → ‘저장 기록 보기’ → 기록 상세 → ‘이 선택으로 문서 검토’를 누릅니다.
- 현재 대상·근거·지침·형식을 직접 확인하고 ‘현재 문서 상태 확인’을 누릅니다.
- 문서 버전·해시와 별도 검토 요청 확인란을 확인한 뒤 ‘검토 시작’을 누릅니다.
- 요청문을 자동 해석하지 않습니다. 기록 저장만으로 검토가 시작되지 않습니다.
- 실행은 checklist_review이며 항목·근거·미해결 사항과 실제 원문을 로컬에 표시합니다.
  보완·변환·최종 승인·업무 파일 저장은 하지 않습니다. 승인 대기 작업은 그대로 둡니다.
- 검토 결과와 읽은 본문은 stateDir에 .request-reviews를 붙인 별도 로컬 폴더에 남습니다.
  결과 JSON은 1.5MB 이하이며 초과·권한 오류·문서 변경을 완료로 표시하지 않습니다.
- 원래 기록·본인 해석·부분 주석은 유지합니다. 결과 열람 후 해석 수정에는 노출 이력을 남깁니다.
- 이력에서 결과를 다시 열 수 있습니다. 불확실한 실행은 같은 실행 ID로 결과만 확인하며
  자동 재실행하지 않습니다. 새 검토는 현재 선택의 별도 재확인이 필요합니다.
- 0.3.2의 AppData 설정 읽기와 업무 미연결 새 기록 작성 수정을 유지합니다.

시작 오류 수정 (0.3.2)
- AppData의 공용 연결 설정을 읽지 못해 DESKTOP_START_FAILED가 발생하던 문제를 수정했습니다.
- 기존 설정을 재사용합니다. 문서 수집의 AppData 접근 제한은 유지합니다.
- 최근 업무 요청이 없어도 ‘새 요청 작성’을 열 수 있도록 수정했습니다.

요청 기록 (0.3.1, 선택 기능)
- PC 화면 왼쪽 ‘요청 기록 · 이 PC에만’에서 새 요청을 직접 작성합니다.
- 당시 후보·설정과 의도를 확인하고 ‘확인하고 기록 저장’을 눌러야 저장됩니다.
- 업무 승인/실행과 별개이며, 사용자 본인 확인 개발자료 후보입니다.
- 목록·상세·해석 수정 이력·JSON 내보내기·개별 삭제를 제공합니다.
- 저장 위치는 worker.json의 stateDir에 .request-records를 붙인 별도 폴더입니다.
- 문서 본문·인증키·파일 경로를 요청란에 붙이지 마세요.
- 연구 모델·자동 학습·새dev/final 편입은 연결하지 않습니다.
- 새 ZIP은 별도 폴더에서 사용합니다. 실행 중인 worker와 기존 설치본을 덮어쓰지 않습니다.

1. ZIP 전체를 쓰기 가능한 로컬 폴더에 압축 해제합니다.
2. DIANA.exe를 실행합니다. EXE만 다른 곳에 옮기지 마세요.
3. 기존 PC 연결 설정이 있으면 실행과 동시에 자동 연결합니다.
   처음 사용하는 PC에서만 ‘연결 설정’에서 기존 worker.json,
   AGENT_TOKEN이 있는 .env, 일반 DIANA 파일 폴더를 한 번 선택합니다.
4. 설정을 저장하면 바로 연결하고 PC 검토 화면이 기본 브라우저에 열립니다.
5. ‘연결 종료’ 또는 창의 X는 진행 중 처리를 기다린 뒤 worker를 종료합니다.
   브라우저 탭만 닫으면 worker는 계속 실행합니다.

자동 연결 (0.2.1)

연결에 성공하면 설정 파일 경로와 서버 주소만 이 PC에 기억합니다.
연결 키 내용은 공통 설정에 복사하지 않습니다.
공통 설정: %LOCALAPPDATA%\DIANA\financial-desktop\desktop.json
새 버전을 다른 폴더에 압축 해제해도 이 설정을 재사용합니다.
실행 폴더의 .local\desktop.json이 있으면 그 설정을 먼저 사용합니다.
--settings로 지정한 별도 테스트 설정은 공통 설정을 바꾸지 않습니다.

문서와 작업 등록 (0.2.0)

1. PC 검토 화면 왼쪽의 ‘문서 · 작업 등록’을 누릅니다.
2. 검토할 문서·근거 자료·검토 지침을 각각 선택해 PC에 등록합니다.
   TXT·MD·JSON(UTF-8, 256KB 이하)을 지원하며, 지침은 기존 rules 형식의
   JSON입니다. 지침의 id/version은 문서 코드/버전과 맞아야 하고,
   source_ids는 선택한 근거 자료의 문서 코드와 맞춰 주세요.
3. 작업 이름, 검토할 문서, 근거 자료, 지침, 보완 항목과 형식을 선택합니다.
4. 작업 등록 후 ‘모바일 작업 목록 반영 완료’를 확인합니다.
   모바일 금융 문서 모드에서 새로고침하면 새 작업을 선택할 수 있습니다.

등록 파일은 PC 전용 사본입니다. 원본을 수정해도 등록본은 자동으로
바뀌지 않습니다. 변경된 자료는 새 문서 코드로 등록해 주세요.
기존 문서/작업 수정·삭제 대신 새 등록을 추가하는 방식입니다.
검토·승인·저장 중에는 새 등록을 막아 기존 수정안을 보존합니다.
모바일에는 작업 이름·동작·형식만 전달하며 파일명·문서 코드·경로와
본문은 전달하지 않습니다. 연결이 끊기면 PC 등록 상태로 대기합니다.

이 실행기는 기존 Render 서버와 금융 요청·상태 API를 사용합니다.
문서·근거·수정안·결과 파일·최종 승인은 PC에 유지합니다.
다른 PC에는 그 PC에서 검토한 작업·문서·권한 설정과 연결 키가 필요합니다.
배포 ZIP에는 사용자 설정·연결 키·원문·결과 파일이 없습니다.
실험용 동결 Byte 모델과 NumPy가 포함됩니다. 기본은 수동 선택이며 자동 학습은 없습니다.

Node와 Python 런타임을 함께 제공합니다. 기존 core.json의 python 경로는
자동 변경하지 않습니다. 새 PC용 설정을 만들 때는 이 폴더의
runtime\python\python.exe 절대 경로를 등록할 수 있습니다.
현재 가상 작업 생성 도구: app\scripts\init-financial-mobile-demo.mjs
이 도구는 개발자용이며 사용자 문서를 자동으로 등록하지 않습니다.

동일 Windows 로그인에서는 실행기 창 하나만 사용합니다.
기존 CMD 금융 worker가 실행 중이면 기존 창에서 exit로 종료한 뒤 연결합니다.
학습 프로그램이나 일반 DIANA 에이전트에는 영향을 주지 않습니다.
연결이 끊기면 자동 재시도하며, 원문과 결과는 PC에 남습니다.

Windows 10/11 x64 및 .NET Framework 4.8이 필요합니다.
현재 EXE는 코드 서명 전 개발 배포본입니다.
로컬 실행 검증은 이 PC에서 수행하며 다른 PC 실기기 검증은 별도입니다.
라이선스·구성 파일 해시는 LICENSES 및 manifest.json에서 확인할 수 있습니다.


0.3.5 학습자료 검토·교정
PC 로컬 화면 → 요청 기록 → 저장 기록 상세 → 학습자료로 검토.
① 뜻 ② 문서 역할·형식 ③ 실제 원문의 구간 ④ 문제 이유를 직접 확인하고,
네 가지 본인 확인을 체크한 뒤 오류 검사 → 본인 검토 완료 → 교정 새 버전 저장.
요청 기록 화면의 교정 자료 묶음 내보내기에서 완료본을 선택합니다.
큰 JSON 편집은 필요 없습니다. 이름의 첫 등장은 자동으로 정답이 되지 않습니다.
교정본은 설정 stateDir 뒤 .corrections, 묶음은 .correction-bundles 폴더에 저장합니다.
질문·취소는 인자를 학습하지 않습니다. 실제 언급이 없거나 원본이 바뀐 자료는 제외합니다.
기능 검증용 가상 기록은 기본 학습 내보내기에서 제외합니다.
내보내기는 학습·평가 준비 완료가 아닙니다. 원천·계보 검토와 분할 결정은 별도입니다.
본인 검토이며 독립 A/B 주석이 아닙니다. 모델 학습·가중치 교체·업무 실행은 하지 않습니다.
기존 설치본을 덮어쓰지 말고 별도 폴더에서 실행하세요.
