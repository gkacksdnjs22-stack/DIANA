# 관리자 패스키 운영 반영 준비

2026-11-03 사용자 정정: 운영 관리자용 주소는 아직 만들거나 확정하지 않았다. 기존 DIANA 서버 주소를 관리자 인증 출처로 단정하지 않는다. 이 문서는 준비안이며 운영 배포·DB 변경·인증서 발급 승인이 아니다.

## 출처와 단일 서비스 구성

- 운영 Origin: 미정. 관리자 화면을 제공할 실제 주소를 먼저 확정한다.
- 운영 RP ID: 미정. 확정한 HTTPS Origin과 일치하는 검증 정책을 별도 검토한다.
- 현재 만들어진 관리자 시험 출처는 `https://diana-admin-passkey-stage.onrender.com`이다. 기존 DIANA 서비스 URL이 조회된 사실을 운영 관리자 주소의 확정으로 간주하지 않는다.
- 운영 Origin/RP ID가 정해지면 해당 출처에서 관리자 인증 수단을 새로 등록하는 절차를 준비한다. 시험 계정·키·세션·초기 토큰을 운영으로 복사하지 않는다.
- 운영 DIANA 서버 안에 별도 관리자 인증 라우터와 전용 경로를 추가하는 방식으로 준비한다. 예시 경로 `/admin/auth/`는 기존 API 충돌 확인 후 확정한다. 인증 서비스 분리는 현 단계의 요구가 아니다.
- 기존 앱·문서 API·문서 승인 흐름을 대체하지 않는다. 운영용 인증 테이블/스키마와 최소 DB 권한, 마이그레이션·롤백은 별도 PR에서 검토한다. 학습·평가 데이터는 대상에서 제외한다.
- 현재 `stageConfig`와 클라이언트 생성기는 시험 DB/출처만 허용한다. 운영에 시험 서버나 시험 APK를 그대로 올리거나 가드만 해제하지 않는다. 운영용 구성과 경로를 별도로 검토·구현한 뒤 복제 환경에서 확인한다.
- HTTPS 출처에서 시스템 브라우저로 인증하고 PC loopback 반환과 Android 앱 반환은 PKCE·state·정확한 redirect 검증을 유지한다. localhost를 운영 RP로 취급하지 않는다.

## 배포물과 키 보관

현재 확인: HTTPS 시험 APK는 별도 package의 debug 서명이며, 시험 EXE의 Authenticode 상태는 `NotSigned`다. 운영 배포 전에 Android 운영 서명키의 소유자·보관·오프라인 백업·업데이트 경로, Windows 코드 서명과 업데이트 정책을 정한다. 이 점검에서 운영 서명키나 인증서를 새로 생성·구매하지 않았다. 시험 debug 키는 운영 서명키로 재사용하지 않는다.

패스키 개인키는 OS/인증기에서 관리하고 서버에 백업하지 않는다. 앱의 세션 저장소와 인증기 개인키 보관은 구분한다. 동기화 키는 기기 하나와 같지 않다. 분실한 기기만 영구 해제해야 한다면 별도 기기 등록 또는 기기 귀속 인증기 정책을 먼저 정한다.

## 최초 등록과 복구 운영 절차

1. 운영 초기 설정 담당자와 초기 owner의 신원을 확인하고, 만료·단회 등록 절차로 새 패스키를 등록한다. 운영 초기 토큰은 서버에 해시만 저장하고 원문은 담당자에게 비공개 전달한다.
2. 운영 전 추가 인증 수단과 복구 코드를 준비한다. 원문 복구 코드는 서버·채팅·이슈·클라이언트 배포물에 보관하지 않는다. 복구 코드의 보관 담당자·장소·분실 통보 절차를 지정한다.
3. 분실 신고 시 운영자가 별도 신원 확인을 하고 신뢰된 CLI 실행 환경에서 사전 발급 복구 코드를 사용한다. 공개 HTTP 복구 경로, 임시 공용 관리자 암호, 개인키 서버 백업은 만들지 않는다.
4. 복구 출력은 새 비공개 파일을 독점 확보한다. 파일 저장·동기화·닫기와 DB 트랜잭션 성공을 확인한 뒤 등록권을 해당 사용자에게 비공개 전달한다. 등록권 만료와 단회 사용을 지킨다. 복구 완료 전 임의 DB role 변경으로 우회하지 않는다.
5. 기존 키·세션·갱신 수단의 무효화를 확인하고, 새 키 등록 뒤 남은 옛 복구 코드를 무효화한다. 새 복구 코드는 재인증 후 별도로 발급·보관한다.
6. 복구 코드까지 잃으면 자동 승격이나 코드 없는 CLI 우회를 제공하지 않는다. 조직의 별도 신원 확인과 새 환경 재구축 절차로 에스컬레이션한다.

시험에서 사용한 임시 외부 /32 허용은 이미 제거됐다. 운영 복구 실행 환경은 아직 미확정이며, 시험 PC에 운영 DB를 상시 개방하는 계획으로 대체하지 않는다. 담당자·실행 환경·필요 최소 DB 접근 권한은 운영 반영 전 결정 사항이다.

## 운영 전 확인과 승인

- 실제 Render 프록시 체인과 신뢰 경계를 확인하고 접속원별/익명/인증 계정 한도를 각각 검사한다. 지금은 전달 헤더를 임의로 신뢰하도록 변경하지 않았다. 원문 IP·헤더·토큰을 상시 감사 로그에 추가하지 않는다.
- 운영 DB 백업·복구·보관 정책, 실패 알림과 최소 감사 로그, 도메인 수명과 이전 절차를 정한다. 무료 시험 DB 만료 예정일 2026-12-02를 운영 보관 계획으로 사용하지 않는다.
- 별도 시험 계정으로 실제 휴대폰 키 등록, APK admin 세션, 웹에서 그 키 폐기, APK 기존 세션 거절을 확인한다. 기존 owner 키는 유지한다. 소프트웨어 인증기 검사와 실기기 확인을 분리해서 기록한다.
- 마이그레이션 전 백업·호환성·롤백 절차를 검토한다. 애플리케이션 롤백이 폐기된 키나 기존 세션을 다시 활성화하지 않아야 한다.
- 정확한 배포 커밋·대상 서비스·구성·서명된 배포물·초기 등록 담당자와 검증 결과가 준비된 뒤 운영 반영 승인을 받는다. 그 전에는 운영 서비스와 기존 앱을 변경하지 않는다.
