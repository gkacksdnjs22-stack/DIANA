# DIANA — AI 원격비서 시제품

사용자가 잠들기 전에 원본·목표·검토 기준·기한을 지정하면, 연결된 PC가 원문을 바탕으로 보고서를 만들고 최대 3회 검토한 뒤 편집 가능한 발표자료를 생성하는 시제품입니다. Android 앱은 결과 파일의 해시를 확인하고, 기한 전에 저장을 확인한 경우에만 화면에 완료로 표시합니다. 기존 ‘길’ 프로젝트와 별도입니다.

2026-10-23 Render HTTPS 배포와 갤럭시 SM-S711N에서 실제 Groq 문서 수정·보고서 생성을 확인했습니다. 보고서 MD·HWPX·PDF와 6장 발표자료 PPTX·PDF 다섯 파일은 서버 다운로드 해시와 갤럭시 저장 확인 응답까지 검증했습니다. 사용자가 별도로 요청한 7장 발표자료도 모바일 수신과 PPTX 전체 렌더·내용 검사를 통과했습니다. OpenAI API 실호출, 실제 PC 원격 부팅, 외부 메일 발송은 별도 검증이 필요합니다.

## 현재 동작 범위

| 기능 | 현재 상태 |
|---|---|
| 휴대폰 크기의 웹 요청 화면 | PC 문서 목록, 밤사이 위임, 작업 진행, 기기 페어링 코드 화면 구현 |
| 제어 서버 | 예약 보관·마감·PC 폴링, 휴대폰 등록/해제, 결과 목록·해시 확인 ACK 구현 |
| 보고서 작업 | 원본 해시를 고정하고 OpenAI Responses API 또는 Groq로 초안·최대 3회 검토/수정. Groq 실제 생성·갤럭시 수신 검증 완료 |
| 보고서·발표자료 출력 | Markdown 보고서와 편집형 PPTX에 더해 보고서 HWPX·PDF, 슬라이드 PDF를 생성. HWPX 왕복 파싱·PDF 페이지/본문 검사 및 시각 렌더 확인 완료 |
| Android 앱 | Keystore 토큰 저장, WorkManager 동기화, SHA-256 검사, 파일 열기/공유, 선택 폴더 복사 구현. APK 빌드됨 |
| 휴대폰 자동 저장 | 앱은 주기적으로 확인해 저장·해시를 검증. FCM 서버 설정이 없어 기본 확인 주기는 15분이며 OS 절전은 지연 가능 |
| 원격 전원 신호 | WoL 게이트웨이 코드 있음. 공유기·PC MAC·BIOS 설정 및 실제 전원 켜기는 검증 전 |
| 문서 읽기 | TXT/MD·PDF·DOCX 및 [Kordoc 4.24.1](https://github.com/chrisryugj/kordoc) 기반 HWP/HWPX/HWPML·XLS/XLSX/PPTX 읽기. Kordoc은 MIT 라이선스이며 OCR은 네트워크 모델 다운로드를 막기 위해 끔 |
| 개발 파일 편집 | UTF-8 텍스트·Python·JSON·자주 쓰는 코드/설정 파일의 수정본 생성. 원본은 유지하고 JSON 문법은 저장 전 검증 |
| 단건 검색/메일 | 코드·설정·사무 문서 검색과 SMTP 연습/연결 어댑터 유지 |
| 휴대폰→PC 파일 보내기 | 웹·앱에서 파일 1개(최대 10MB)를 명시적으로 전송. PC가 크기·SHA-256을 확인한 뒤 전용 수신 폴더에 저장하고 완료 응답. 새 서버·APK 배포와 실기기 검증 대기 |
| 원본 폴더 자동 이동 | 전용 수신 폴더까지 저장하며 다른 원본 파일을 덮어쓰거나 자동 이동하지 않음 |

## 로컬 실행 — Windows PowerShell

Node.js 24 이상이 필요합니다.

```powershell
cd 'C:\work\diana'
npm.cmd ci --ignore-scripts
npm.cmd run setup
npm.cmd start
```

다른 터미널에서:

```powershell
cd 'C:\work\diana'
npm.cmd run agent
```

`http://127.0.0.1:3411`을 열고 `.env`의 **USER_TOKEN 값만** 연결 코드에 입력합니다. 현재 개발 PC는 이 포트를 사용하며, USB 연결 검증에는 `adb reverse tcp:3411 tcp:3411`을 사용했습니다. 초기 검색 폴더는 실제 개인 자료가 아닌 `sample-documents`입니다.

밤사이 위임은 PC 에이전트가 온라인이고 원본 목록을 동기화한 뒤 사용할 수 있습니다. 초기 설정은 AI가 아닌 키워드 검색이므로 아래 안내에 따라 `.env`에 OpenAI 또는 Groq 제공자를 설정합니다. OpenAI는 PowerShell에서 `& .\scripts\configure-ai.ps1`을 실행해 API 키와 사용할 수 있는 Structured Outputs 모델 ID를 로컬 입력창에 입력할 수도 있습니다. 키와 문서 내용은 채팅에 붙이지 마세요. API 사용량은 선택한 제공자의 계정에 적용되며, 지정한 원문 일부가 해당 API로 전송됩니다.

갤럭시 APK: [DIANA-debug.apk](./앱-설치/DIANA-debug.apk). 런처 이름과 아이콘은 DIANA 브랜드를 사용합니다.

예시: `가람상사 2026년 9월 매출 보고서 최종본`을 찾아 ‘휴대폰에 파일 저장’으로 요청 → PC 프로그램이 후보를 돌려줌 → 파일 선택 → 다운로드. ‘메일 발송’을 선택해도 기본 `MAIL_MODE=dry-run`에서는 `.local/outbox`에 첨부가 들어간 연습 메일을 만들며 외부로 보내지 않습니다.

초기값 `AI_MODE=lexical`은 **AI가 아닌 키워드 검색 시연**입니다. AI 내용 판단·수정은 PC의 `.env`에서 제공자를 설정합니다. OpenAI는 `AI_MODE=openai`, `OPENAI_API_KEY`, `OPENAI_MODEL`을 사용합니다. Groq는 `AI_MODE=groq`, `GROQ_API_KEY` 또는 기존 이름인 `GROQ_OPENAI_KEY`를 사용하고, `GROQ_MODEL`의 기본값은 `openai/gpt-oss-120b`입니다. [Groq Structured Outputs](https://console.groq.com/docs/structured-outputs)의 strict JSON schema 방식으로 검색·문서 수정·밤사이 보고서 생성을 처리합니다. 모델은 사용하는 계정에서 지원되는 Structured Outputs 모델로 지정합니다. API 키는 PC에만 보관합니다.

설정을 저장한 뒤 `npm.cmd run ai:check`로 가상 문서 한 건을 이용한 실제 연결·JSON 구조·원문 근거 검증을 실행할 수 있습니다. 실행 중인 PC 에이전트는 재시작해야 변경된 설정을 읽습니다. Groq 검색 결과는 기존 서버의 AI 검색 형식으로 전송하므로 제공자 변경만을 위해 서버를 다시 배포하지 않아도 됩니다.

AI 모드를 선택하면 지정 문서에서 추출한 제한된 텍스트가 선택한 제공자의 API로 전송됩니다. 키나 개인정보가 들어갈 수 있는 개발 파일·설정 파일은 `DOCUMENT_ROOT`에 넣기 전에 확인하세요. OpenAI의 `store:false`는 응답 저장 옵션이며 완전한 무보관이나 로컬 처리 보장은 아닙니다. Groq에는 지원하지 않는 `store` 옵션을 보내지 않습니다.

## 휴대폰 파일을 PC로 보내기

새 서버와 APK를 배포한 뒤, 앱의 ‘PC로 보낼 파일 선택’에서 파일 하나를 고르고 이름·크기를 확인한 다음 ‘PC로 보내기 / 재시도’를 누릅니다. 웹의 파일 보내기 영역에서도 요청할 수 있습니다. 빈 파일은 제외하며 최대 10MB입니다. 전송 준비 사본과 같은 전송 번호를 보관하므로 네트워크가 끊기거나 앱을 다시 열어도 같은 파일로 재시도할 수 있습니다. 휴대폰 원본은 유지됩니다.

서버 수신과 PC 저장은 별도 상태입니다. PC가 온라인이면 크기와 SHA-256을 검증한 뒤 `DOCUMENT_ROOT/휴대폰에서_받은파일/<전송 ID>/<원래 파일명>`에 저장하고 ‘PC 저장 완료’를 표시합니다. 지원하는 형식의 문서는 PC 문서 목록과 검색에서도 찾을 수 있습니다. 기존 원본을 덮어쓰지 않습니다. PC가 오프라인이면 서버에서 최대 24시간 기다리며, 기간이 지나면 파일을 다시 보내야 합니다.

## DIANA로 새 APK 받기

새 서버 배포와 APK 빌드가 끝나면 PC에서 다음 명령으로 설치 파일을 기존 DIANA 앱에 전달할 수 있습니다. 로컬 `.env`의 `USER_TOKEN`을 사용하며 키를 명령에 직접 넣지 않습니다.

```powershell
node --env-file=.env scripts/send-phone-file.mjs "앱-설치/DIANA-debug.apk"
```

갤럭시의 기존 DIANA 앱에서 저장 폴더를 선택하고 ‘지금 결과 확인’을 누르면 최근 작업과 저장 파일에 APK가 들어옵니다. 파일 수신 후 Android의 ‘내 파일’에서 해당 저장 폴더의 APK를 열어 설치합니다. 파일 전달이 자동 설치를 실행하지는 않습니다.

## 밖에서 실제로 쓰려면

PC를 깨울 제어 서버가 **바로 그 꺼지는 PC에만 있으면 작동하지 않습니다.** Render HTTPS 서버를 통한 요청·결과 수신과 서버 재시작 후 기록 유지까지 확인했습니다. 실제 원격 부팅에는 아래 전원 중계기와 PC 설정이 추가로 필요합니다.

1. 제어 서버를 HTTPS 호스트에 배포합니다(Node 24). 로컬은 SQLite를 사용하지만, Render 무료 배포는 디스크가 휘발성이므로 Supabase Postgres + 비공개 Storage 연결이 필요합니다. 설정 방법은 [Supabase 무료 연결 안내](docs/supabase-free.md)를 확인하세요. Cloudflare Workers용 코드는 아닙니다.
2. 집 안에는 WoL 지원 공유기 또는 항상 켜져 있는 소형 중계 기기를 둡니다. 이 기기에서 `gateway/run.mjs`를 실행합니다. 지원 공유기의 WoL API를 사용하려면 별도 어댑터가 필요합니다.
3. PC에 에이전트를 설치하고 부팅 시 시작되도록 운영체제 서비스로 연결합니다. 현재 저장소는 서비스 설치나 자동 로그인 설정을 수행하지 않습니다.
4. 각 기기에 필요한 토큰만 배포합니다. 중계기는 문서나 메일 정보를 받을 필요가 없습니다. PC 메일 계정과 AI 키는 PC에 둡니다. `.env`를 휴대폰이나 공유 저장소에 통째로 보내지 마세요.
5. Android 앱은 HTTPS 제어 서버 주소와 6자리 일회용 코드로 페어링합니다. 현재 FCM 프로젝트가 설정되지 않아 앱이 네트워크 사용 가능 시 WorkManager 15분 주기로 확인합니다. Android 절전 정책에 따라 지연될 수 있습니다.

PC에 직접 접속할 포트를 여는 방식 대신 PC와 중계기가 HTTPS 제어 서버에 접속하는 구조입니다. 현재 배포는 단일 사용자 프로토타입이며, 다중 사용자 서비스에는 계정 인증과 사용자별 권한 분리가 필요합니다.

## 안전하게 처리하는 범위

- 에이전트는 지정한 `DOCUMENT_ROOT` 안에서만 사무 문서와 코드·설정 파일을 읽습니다. 선택 후 내용이 바뀐 파일은 다시 찾도록 합니다. 편집은 UTF-8 텍스트 파일만 별도 수정본을 만들며 원본을 덮어쓰지 않습니다. JSON은 파싱 검증을 하고 Python 등 다른 코드의 실행·동작 검증은 자동으로 하지 않습니다.
- 문서 안의 문장은 검색 자료이며 실행 명령이 아닙니다. AI가 임의 경로·수신자·운영체제 명령을 지정하지 않습니다.
- 기본은 후보 확인입니다. 자동 전달은 사용자가 선택한 작업에서 AI 후보가 단 하나이고 설정한 기준을 넘을 때만 진행합니다. 이 점수는 정확성 보장이 아닙니다. 보고서 예약 작업은 원본 파일과 해시·목표·검토 기준·기한을 확정한 뒤 실행합니다.
- SMTP 접수와 수신함 도착을 구분합니다. 전송 결과가 불명확하면 같은 작업을 자동 재전송하지 않습니다. Gmail·네이버·Outlook·회사 메일의 실제 연결 조건은 `docs/메일연결.md`에 있습니다.
- 휴대폰 다운로드용 파일은 제어 서버에 임시 중계됩니다. 현재 24시간 이후 다운로드를 거부하며 만료 파일을 정리합니다. 실제 서비스는 암호화 저장·기기별 접근·용량 제한·삭제 정책을 추가합니다.
- 검색은 최대 100개 문서, 문서당 10MB, 추출 텍스트당 12,000자 범위입니다. 스캔 PDF와 문서 안 이미지의 OCR은 꺼져 있으며, 긴 문서 뒤쪽 내용이 잘릴 수 있습니다.

## 구조

```text
휴대폰 요청 화면 / Android 연결 앱
                 │ HTTPS
         계속 켜져 있는 제어 서버
            ┌────┴─────┐
      전원 중계기       PC 에이전트
      (집 안 LAN)       (부팅 뒤 접속)
            │           │
           WoL ───→  문서 검색·수정·검토
                        │
                폰 파일 중계 / 메일 전송
```

보고서 워크플로는 초안·검토·수정·검증·Markdown/HWPX/PDF 보고서 및 PPTX/PDF 발표자료 생성·서버 등록까지 연결합니다. HWPX는 kordoc으로 생성한 뒤 다시 파싱해 핵심 문구를 확인하고, 보고서 PDF의 한글 텍스트와 발표 PDF의 페이지 수를 검사합니다. 발표자료 PDF는 슬라이드 미리보기에서 만든 열람용 이미지 PDF이므로 텍스트 검색·복사는 지원하지 않으며, 편집은 PPTX에서 합니다. 숫자와 인용이 고정 원문으로 검증되지 않거나 검토 문제가 남으면 결과를 완성본으로 표시하지 않습니다. 실제 품질과 제시간 도착은 원문·API·PC 전원·네트워크·Android 절전에 달렸습니다. 파일 생성 후에도 갤럭시가 기한 안에 저장 ACK를 보내야 기한 내 완료로 표시합니다.

## 검증

```powershell
npm.cmd test
```

2026-10-23 Node.js 전체 회귀 테스트 246개가 통과했습니다. 테스트는 문서 파싱·경로 이탈·해시 변경·인증·중복 요청·양방향 파일 전달·메일 중복 억제·검토 반복·시간 경계를 검증합니다. 자동 테스트의 AI 응답과 SMTP는 mock이며, WoL UDP 테스트는 `127.0.0.1`로만 보냅니다. 별도로 가상 자료를 사용한 실제 Groq 수정·보고서 생성, Render HTTPS 중계, 갤럭시 저장·해시 확인과 6장·7장 PPTX 렌더 검증을 완료했습니다. Render 재시작과 앱 재설치 후 최근 작업 유지도 사용자가 확인했습니다. 새 휴대폰→PC 기능은 모의 휴대폰의 실제 HTTP 업로드부터 PC 저장·문서 검색까지 로컬에서 확인했으며, 새 APK의 Android 테스트·빌드·실기기 전송 검증은 아직입니다.
