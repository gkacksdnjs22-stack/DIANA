# DIANA 관리자 운영 연결 준비

이 문서는 운영 배포 완료를 뜻하지 않는다. `production-config.mjs`와 설정 예시는 실행 중인 서버에 연결하지 않았으며 기본값은 비활성이다. 기존 운영 서비스·앱·DB·학습/평가 작업은 변경하지 않는다.

## 현재 확인된 연결 지점

- 기존 `server.mjs`는 `createControlServer`를 만든 뒤 바로 listen한다. 관리자 모듈을 import하거나 mount하지 않는다.
- `/admin/`, `/admin/api/`용 `router.mjs`와 `mount.mjs`는 준비돼 있다. 기존 listener 하나를 보존한 채 listen 전에 연결해야 한다.
- 운영 앱의 기존 `DATABASE_URL`은 기존 상태/전송 저장소용이다. 관리자 인증 DB 비밀번호나 권한으로 재사용하지 않는다.
- 시험 `StageStore`는 `diana_admin_stage_v1` 스키마를 고정 사용한다. 새 설정에서 스키마 이름만 바꿔 이 저장소를 운영 어댑터로 간주할 수 없다. 시험 `stageConfig`의 DB·Origin 가드도 해제하지 않는다.
- 원래 DIANA 디자인, WebAuthn·재인증·계정 정리·세션 만료 작업은 시험에서 검증했다. 이는 운영 DB나 최종 출처의 검증을 대신하지 않는다.

## 이번에 준비한 것

`productionAdminConfig(env)`는 전달된 값만 검사한다. `.env`를 읽지 않고 DB에 연결하거나 스키마를 생성하지 않는다. `DIANA_ADMIN_ENABLED`의 기본값은 false이며 true 외의 활성화 표현은 거절한다. Origin/RP ID, 시험 DB·스키마 분리, 별도 DB 자격 증명, 명시적 TLS/사설망 전송, 실제 확인된 프록시 IP를 요구한다. URL의 TLS 우회 매개변수는 거절한다.

`inspectProductionAdminConfig(env)`는 DB URL·암호·입력 원문 없이 고정 오류 코드와 준비 상태만 반환한다. 올바른 형식이어도 `deploymentReady:false`다. 실제 연결·운영자 등록·런타임 마운트는 별도 검증해야 한다. 설정 객체 자체에는 DB URL이 있으므로 로그·이슈·클라이언트에 직렬화하지 않는다.

`production.env.example`은 값이 비어 있고 비활성인 예시다. Render 환경 변수에 아직 입력하지 않는다. 실제 비밀값은 플랫폼 비밀 저장소에서만 관리한다. 기존 시험 패스키·owner·세션·복구 코드를 운영으로 복사하지 않는다.

## 다음 작업 순서

1. 최종 관리자 HTTPS Origin과 RP ID를 확정한다. 조회된 기존 운영 URL이나 현재 시험 URL을 자동 선택하지 않는다.
2. 전용 운영 인증 DB·최소 권한 계정·`diana_admin_prod_v1` 스키마의 어댑터와 마이그레이션을 준비한다. 실제 current_database/스키마/권한을 확인하고 백업·복원 및 롤백을 복제 환경에서 검증한다.
3. 위 설정 모듈을 이용하는 별도 운영 초기화 코드를 만들고, 검토된 인증 어댑터를 `createAdminConsole`에 주입한다. 기존 listen 전에 mount하고 비활성일 때 기존 서비스 동작이 동일한지 검증한다. 종료 시 세션 정리 작업을 기다린 뒤 DB를 닫는다.
4. Render TLS 종료·실제 프록시의 신뢰 IP를 확인한다. 임의의 전달 헤더, wildcard 프록시, 외부 DB 전체 개방으로 대체하지 않는다.
5. 신뢰된 운영자 절차로 최초 owner의 만료되는 등록권을 발급하고 최종 출처에서 실제 패스키를 새로 등록한다. 추가 인증 수단·복구 코드 보관과 복구 담당자를 준비한다. 공개 복구/초기 승격 경로를 만들지 않는다.
6. APK/EXE의 운영 client/redirect/PKCE, Android 서명·EXE 코드 서명·배포 경로는 별도로 준비한다. 이 설정 모듈은 native 경로를 활성화하지 않는다.
7. 출처·만료·재사용·무권한 요청·권한 변경/폐기 후 세션 차단·오프라인 거절을 운영 복제 환경에서 검증한다. 서버 인증과 PC 문서 승인 경계를 유지한다.
8. 정확한 커밋·대상 서비스·복구/롤백 방법을 검토한 뒤 운영 배포 승인을 받아 Render에 반영한다. 애플리케이션 롤백으로 DB 삭제/폐기가 되돌아온다고 가정하지 않는다.

운영 관리자 주소·DB·프록시·초기 운영자 등록은 아직 미확정이다. 이 준비 PR을 병합하는 것만으로 운영 인증이 활성화되지는 않는다.
