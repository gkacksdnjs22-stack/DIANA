# 디아나 (Diana) — 24시간 비동기 AI 업무 비서

<p align="center"><img src="./assets/diana-logo.png" alt="디아나 공식 브랜드 로고" width="240"></p>

기획 기준일: 2026-10-22 · 출품: 2026 AI 라이프 솔루션 챌린지 · 접수 마감일: 2026-10-31

> **당신이 쉬는 밤에도, 이동 중인 낮에도 — 24시간 빈틈없이 이어지는 AI 업무 비서**

**디아나**는 취침 전이나 외근 이동 전에 한 번 맡기면, 사용자의 PC에서 지정한 문서를 분석·수정·검토하고 보고서와 발표자료를 준비해 모바일로 가져오는 비동기 위임 에이전트다. 사용자는 작업이 끝날 때까지 화면 앞에 머물 필요 없이, 이동 중 핵심 변경점과 확인 항목을 살펴보고 마지막 승인만 한다.

이름은 로마 신화의 달과 사냥의 여신 디아나에서 왔다. 밤사이 작업을 이어가는 달의 이미지와 근거 충돌·오류를 찾아내는 정밀함을 담되, 사용자의 결정을 대신하지 않는 부드러운 동료를 지향한다.

로고는 짙은 남색 바탕에 청록·라일락 빛의 D 심볼과 중앙 조준점을 배치해 탐색과 정밀함을 시각화한다. 이 색과 심볼을 앱 아이콘, 작업 상태 화면, 발표자료의 표지·마지막 장에 일관되게 적용한다.

## 1. 해결할 문제

보고서와 제안서를 완성하려면 자료를 찾고, 수치와 요구사항을 대조하고, 문장을 다듬고, 발표자료를 만들고, 필요한 곳에 전달해야 한다. 사용자가 늦은 밤까지 PC 앞에 있거나 이동 중 작업 파일을 찾는 일이 생긴다. 작업이 길어지면 다음 날 회의·발표 전에 검토할 시간이 사라진다.

디아나는 사용자의 작업을 밤이나 외근 시간으로 이어 받아 결과 후보를 준비한다. 핵심 가치는 일을 무조건 자동 완료한다고 약속하는 데 있지 않다. **사용자가 쉬거나 이동하는 동안 검토 가능한 결과물을 만들고, 불확실한 부분과 남은 결정을 아침 또는 이동 중에 분명히 보여주는 것**이다.

주 사용자는 사무 문서와 개발 파일을 다루는 직장인, 프리랜서, 1인 사업자다. PC가 회사에 있거나 집에 있는 동안 작업이 이어져야 하는 상황을 모두 다룬다. 대상 파일은 보고서·제안서·PDF·HWP/HWPX·Office 문서와 설정·개발 파일인 Python, JSON 등이다.

## 2. 대표 경험과 차별점

### 95% 준비된 결과와 스마트 하이라이트

디아나는 불확실성이 발견됐다는 이유만으로 전체 작업을 멈추지 않는다. 지정한 범위 안에서 가능한 보고서 초안과 10장 안팎의 발표자료를 준비하고, 근거가 충돌하거나 AI가 추정한 내용은 **노란색 하이라이트와 설명 주석**으로 표시한다. 사용자는 전체 문서를 다시 읽는 대신 표시된 부분과 요약된 변경점에 집중한다.

‘95%’는 사람이 마지막 확인만 하면 될 정도로 준비하겠다는 제품 목표이자 표현이며, 정확도 측정 결과를 뜻하지 않는다. 근거가 부족한 부분을 사실처럼 채우지 않는다. 주석이 붙은 검토본과 변경 이력은 보관한다. 모바일에서 사용자가 표시 항목을 확인하고 명시적으로 승인하면, 승인된 범위의 주석·하이라이트를 제거한 클린본을 별도로 생성할 수 있다. 승인은 결과 파일과 수신인·전송 경로 미리보기를 본 뒤 받아 기록한다. 미해결 쟁점을 사용자가 승인하지 않으면 그 자료는 검토본으로 남고 외부 발송은 보류한다.

### 이동 중 대화형 수정과 핸즈프리 확인

지하철·도보 상황에는 짧은 자연어 명령으로 수정 요청을 보낸다. 예를 들어 “3페이지 수치를 매출원장 기준 20억으로 수정하고, 바뀐 부분을 다시 보여줘”라고 요청하면 디아나는 새 버전을 만들고 변경점과 하이라이트를 다시 표시한다.

운전 중에는 화면 조작을 요구하지 않는 음성 대화 UX를 목표로 한다. 실제 전화망을 통한 AI 통화는 음성 AI만으로 완성되지 않는다. 전화번호 연결·통신 사업자/SIP 연동과 안전한 확인 절차가 추가로 필요하다. 초기 데모에서는 모바일 마이크 기반 음성 입력 또는 통화 UX 프로토타입으로 흐름을 보여주며, 실제 전화 연동이 확인되기 전에는 연결됐다고 표시하지 않는다. 운전 중에는 음성으로 요약과 승인 여부를 확인하고, 복잡한 수치 수정·수신인 변경은 정차 후 확인하도록 설계한다.

### 한국형 문서 파싱과 신구대조

Kordoc으로 HWP/HWPX/HWPML, PDF, Office 파일 등을 로컬 PC에서 읽을 수 있는 텍스트와 구조화된 내용으로 변환하고, 수정 전후 차이를 확인하는 파이프라인을 만든다. 공공기관·기업 문서와 기존 파일이 PC에 있는 사용자에게 로컬 에이전트가 필요한 이유다. MCP 어댑터를 통해 문서 파싱·검색·Diff 기능을 에이전트가 표준 도구처럼 호출하는 구성을 목표로 한다. 현재 Kordoc 파싱 연동과 MCP 표준 연결은 구현 상태를 따로 검증하고, 출품 문구에서 연동 완료 여부를 구분한다.

파일 원본과 작업 권한은 PC 에이전트가 관리한다. 다만 외부 AI API를 선택하면 추출한 문서 내용 일부가 해당 API로 전송될 수 있으므로, 로컬 파싱을 곧 완전한 온디바이스 AI 또는 무전송 보안이라고 표현하지 않는다. 민감 문서는 사용자 승인 범위만 전송하고, 장기적으로는 로컬 모델 선택지도 검토한다.

### 밤부터 낮·주말까지 이어지는 위임

작업은 예약된 야간에만 한정하지 않는다. 낮 외근, 회의, 출장, 주말에도 같은 절차로 맡길 수 있다. PC 에이전트는 유선 데스크톱과 Wi-Fi 노트북 모두를 목표로 하며, PC가 켜져 있거나 원격으로 켤 수 있고 에이전트가 온라인이면 작업을 진행한다. WoL은 데스크톱·공유기·BIOS·전원 상태 조합에 따라 작동 여부가 다르므로 실제 검증 결과를 기기별로 표시한다. Wi-Fi 노트북의 절전·종료 상태에서 원격으로 켜지는 기능은 보장하지 않는다.

## 3. 한 번 위임하는 흐름

1. **맡기기:** 사용할 파일과 참고자료, 수정 범위, 마감 시각, 산출물, 허용된 전달 경로를 지정한다. 원본은 보존하고 실행 시점에 해시로 변경 여부를 재확인한다.
2. **분석하기:** PC 에이전트가 허용 폴더 안의 문서를 파싱한다. Kordoc 신구대조와 지정 자료 비교로 주장·수치·요구사항의 근거를 추적한다.
3. **준비하기:** 보고서 Markdown·HWPX·PDF와 10장 안팎의 편집 가능한 PPTX·PDF를 만든다. 수정·검토 과정을 제한된 횟수로 반복하고, 남은 충돌·추정·검증 불가 내용을 주석으로 표시한다.
4. **가져오기:** 결과 파일을 Android 기기에 저장하고 파일 해시를 확인한다. 사용자는 이동 중 요약, 수정 전후 차이, 확인할 항목을 살핀다.
5. **수정·승인하기:** 채팅 또는 음성으로 수정 의사를 전달한다. 수정 결과를 다시 확인한 후 클린본 생성과 발송을 명시적으로 승인한다.
6. **전달하기:** 지정한 테스트 또는 실제 수신인과 경로를 보여주고 전송한다. 휴대폰 저장, 메일 서버 접수, 실제 수신함 도착 상태를 서로 구분해 기록한다.

## 4. 결과 신뢰와 권한 경계

- 읽을 수 있는 폴더, 대상 파일, 수정 범위, 수신인과 전달 경로는 사용자가 정한다. 원문에 적힌 명령문은 자료로 취급하고 실행 지시로 삼지 않는다.
- 편집은 원본에 덮어쓰지 않고 새 버전으로 만든다. 개발 파일은 변경된 줄을 보여주며 JSON은 문법 검증을 한다. Python 등의 코드는 기본적으로 실행하지 않는다.
- 주장의 근거를 찾을 수 없거나 서로 다른 문서가 충돌하면 그 지점을 숨기지 않고 표시한다. 사용자가 확인하지 않은 경고를 자동으로 제거하지 않는다.
- AI가 한 번 “검토 완료”라고 답하는 것만으로 내용 정확성을 보장하지 않는다. 출처·요구사항·문서 구조·파일 열림·보고서와 슬라이드 수치를 각기 확인한다.
- 외부 발송은 클린본, 수신인, 제목, 첨부 파일을 미리 보여준 뒤 명시적 승인으로 실행한다. 전송 응답이 모호하면 중복 발송하지 않는다.
- 메일·메신저 본문과 문서에는 중요한 개인정보나 인증정보를 포함하지 않는다. 키는 PC 로컬 설정에 둔다.

## 7. 성공 측정

아래는 목표 지표이며 아직 측정 결과가 아니다. 동일한 고정 입력자료로 반복 시연해 수치와 로그를 남긴다.

| 지표 | 시연에서 확인할 목표 |
|---|---|
| 위임 간편성 | 사용자가 파일·요구·마감·전달 조건을 한 번에 지정 |
| 문서 준비 | 보고서와 10장 안팎의 PPTX를 요청 마감 전에 생성 |
| 쟁점 가시성 | 사전 구성한 수치 충돌과 AI 추정 항목을 모두 주석으로 노출 |
| 변경 추적 | 원본 보존, 변경 전후 비교, 검토 기록 유지 |
| 모바일 연속성 | 이동 중 수정 요청을 처리하고 갤럭시 저장·해시 ACK 확인 |
| 승인 안전성 | 승인 전 전송 0건, 승인 후 수신인·파일·메일 결과 기록 |
| 실패 투명성 | WoL·네트워크·저장 실패를 완료로 표시하지 않음 |

시간 절감률, 정확도, 실제 사용 만족도는 정해진 비교 시험을 수행한 후에만 결과로 제시한다.

## 8. 공모전 시연에서의 진실성 기준

골든 패스에서 실연결과 모의 화면을 구별한다. 실제 AI 호출, Android 파일 저장 ACK, SMTP 외부 접수, PC 원격 기동, 카카오 메시징, 전화 통화는 각각 독립된 검증 항목이다. 검증하지 않은 기능을 영상 편집이나 음성 연기로 실제 연동처럼 연출하지 않는다.

마감일은 출품 안내 기준 2026-10-31이다. 마감 시각, 제출 양식·필수 파일·접수 조건은 공식 공고를 제출 당일 다시 확인한다.
