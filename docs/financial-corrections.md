# PC 학습자료 검토·교정 (0.3.5)

요청 기록을 사용자가 직접 확인해 **학습자료 후보**로 내보내는 기능이다. 본인 검토이며 독립 A/B 주석이나 외부 평가 정답이 아니다. 실제 사용자 자료가 없어도 기능 검증은 가능하다. 모델 학습·추론·가중치 교체·업무 검토·승인·저장을 호출하지 않는다. 기존 실험용 AI 미리보기는 별도 수동 기능으로 유지한다.

## 사용 순서

1. PC 로컬 화면 → **요청 기록 · 이 PC에만** → 저장 기록 선택 → **학습자료로 검토**.
2. 당시 요청문·허용 후보·확정 형식·기존 본인 확인과 AI/검토 결과 노출 이력을 확인한다. 현재 후보로 과거 입력을 바꾸지 않는다.
3. 요청의 뜻과 수행 상태를 선택한다. 문서 역할은 당시 허용 후보에서 지정한다. 근거는 복수 선택할 수 있다.
4. 문서 옆 구간 목록에서 실제 언급을 선택한다. 모든 이름·ID·alias 일치를 제시하지만 첫 일치나 문장 순서로 정답을 지정하지 않는다. 직접 구간을 고르려면 고정 원문에서 드래그한 뒤 해당 문서의 **선택한 원문 구간 사용**을 누른다. 강조 문구와 UTF-16 `[시작, 끝)`을 확인한다.
5. 부족·사용 불가·모호함의 이유와 근거 종류를 확인한다. 문제 없는 필드도 본인 확인 대상이다. 각 의미·역할·구간·문제 판단의 확인란을 직접 체크하고 **오류 검사**를 누른다. 판단이나 출처를 수정하면 확인란이 해제된다.
6. 작성자·본인 검토자, 실제/합성/기능 검증용 구분, 연구 사용 가능 여부와 근거를 기록한다. **본인 검토 완료**, **보류**, **제외** 중 상태와 이유를 선택하고 새 버전을 저장한다. 미검토 초안도 보존할 수 있다.
7. 요청 기록 화면의 **교정 자료 묶음 내보내기**에서 항목을 선택한다. 최신 원본·교정, 완료 여부, 사용권한, 중복·상충 정답을 검사한 뒤 포함·제외 이유를 보여 준다. JSON 다운로드 외에 전용 로컬 폴더에도 묶음이 저장된다.

## 화면과 계약의 대응

| 사용자 판단 | intent | status 초안 | request issue |
|---|---|---|---|
| 실제 문서 검토 | checklist_review | ready 또는 needs_clarification | 없거나 ambiguous |
| 질문·설명 | question | unsupported | non_action |
| 취소·금지 | cancel | cancel_requested | cancel |
| 보완·변환·저장·내보내기 | patch/convert/save/export | unsupported | unsupported |
| 여러 작업이 섞임 | mixed | unsupported | unsupported |
| 요청 자체가 모호함 | unknown | needs_clarification | ambiguous |
| 아직 검토 안 함 | 정답 미작성 | 정답 미작성 | 자동 unknown 변환 없음 |

고정 변환은 초안일 뿐 네 가지 본인 확인 전 완료할 수 없다. 문서 필드의 `missing`은 미지정, `unavailable`은 후보 밖 또는 역할 불허, `ambiguous`는 구별 불가이다. 형식은 요청문 지정과 당시 확정 설정을 분리한다. 요청 지정과 설정이 충돌하면 형식 값을 비우고 `format.ambiguous`와 충돌 근거를 기록한다.

검토 요청에서 알려진 인자는 유지하고 부족한 필드만 문제로 주석할 수 있다. 실행용 ready 계약과 주석 적합 검사는 다르다. `needs_clarification` 자료를 일괄 제외하지 않는다. 비review의 null/빈 배열은 직렬화 자리이며 인자 정답 감독이 아니다. 내보내는 `supervision.arguments=false`, `argument_supervision=unannotated`와 기존 로더의 review 전용 마스킹을 유지한다. `scores=null`이다.

## 저장·이력·보호

- 설정의 `stateDir` 뒤에 `.corrections`를 붙인 별도 폴더: `<record UUID>-vN.json`. 원본 기록 버전/해시, 입력 해시, 원문 입력, 교정본, 이전 교정 해시, 작성자·검토자·시각, 원천업무·부모·사용권한·노출 이력을 보존한다.
- `stateDir.correction-bundles`: `<bundle UUID>-v1.json`. UUID마다 별도 묶음이며 덮어쓰지 않는다. 브라우저가 저장 경로를 지정할 수 없다.
- 원본 삭제 후에도 교정 이력은 별도 저장소에 남는다. 삭제·수정된 원본이나 바뀐 교정 버전은 후속 내보내기에서 제외된다. 이미 다운로드한 사본은 자동 삭제되지 않는다. 철회가 필요하면 원본/교정 식별자로 사본 관리자에게 별도 반영해야 한다.
- 동일 입력의 중복과 상충 정답, 원천업무 묶음 및 명시한 부모 관계를 manifest에 남긴다. 동일 입력 중복은 하나만 포함하고 상충 정답은 모두 제외한다. 계보·분할은 미확정이며 행 무작위 분할을 하지 않는다.
- AI 노출은 기존 기록의 노출과 저장 시점의 viewed/applied/edited 기록을 보존한다. 브라우저에서 작성한 이력은 사용자 동작 감사자료이며 독립성 증빙으로 승격하지 않는다. 검토 결과 열람도 별도 기록한다.
- 기존 localhost 인증·Origin·본문 제한·경로 경계를 사용한다. 교정 내용은 외부 서버·모바일로 보내지 않는다. 연구 sealed test와 새 final에는 접근하지 않는다.

## 내보내기와 기존 로더 확인

묶음의 `rows`는 기존 로더와 연결되는 `{input,target}`을 포함한다. `input`에는 `schema_version/request/context/candidates`만 있다. `supervision`과 `metadata`는 모델 입력 밖에 둔다. metadata에 원본·교정 버전/해시, 본인 검토 출처, 사용권한, 원천/부모, 노출, 미확정 분할·계보를 기록한다. manifest에 포함·제외, 중복·상충, intent·issue·근거 수·AI 노출별 수량을 남긴다. 기존 자료 병합이나 학습/평가 분할은 하지 않는다.

별도 도구는 파일 읽기와 실제 Char/Byte 전처리의 언급 대응, 마스크·클래스 형식만 검사한다. 모델 인스턴스·가중치·추론·optimizer는 만들지 않는다. Windows 번들 폴더에서 다음처럼 실행한다.

```powershell
.\runtime\python\python.exe -I -B .\app\financial-documents\check-correction-bundle.py "묶음 JSON의 전체 경로"
```

기능 검증용 자료는 기본 학습 내보내기에서 제외된다. 별도 체크박스로 검증용 묶음을 만들면 `purpose=fixture_validation_not_training`으로 표시된다. 모든 묶음은 `training_ready=false`, `evaluation_ready=false`, `split_assigned=false`이다.

## 제한

이름이 없는 클릭 선택, 후보 밖 문서의 가짜 ID, 구별되지 않는 공통 alias, 지원하지 않는 형식 표현의 구간은 현재 모델용 감독으로 완료할 수 없다. 보류·제외 이력은 보존한다. 이름 매칭은 문자 정규화와 모든 실제 위치를 사용하지만 의미 정답을 보장하지 않는다. 계보 정보와 연구 사용권한은 사용자가 제공해야 한다. 독립 평가로 사용하려면 별도 접수·독립 주석·감사 절차가 필요하다.

검증 증거와 Windows ZIP의 최종 경로는 `.local/correction-verification/`에 저장한다. 가상 검증 자료는 실제 사용자 자료 및 독립 평가 자료 수에 포함하지 않는다.
