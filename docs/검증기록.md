# 구현·검증 기록

기록일: 2026-10-22 (Asia/Seoul)

- 실행 환경: Windows 11, Node.js v24.20.0, npm 11.19.0.
- `npm.cmd test`: 전체 87개 통과. 문서 루트 경계·원본 해시·메일 중복 억제·예약 마감·페어링·파일 수신 확인을 포함한다.
- `android-app/:app:assembleDebug`: 성공. Android SDK 35로 개발용 APK를 생성했다. 컴파일 오류를 수정한 후 빌드가 완료됐다.
- ADB: 갤럭시 SM-S711N(`device`) 승인. `adb reverse tcp:3411 tcp:3411` 성공.
- 갤럭시 실기기 수신: 6자리 페어링과 `adb reverse tcp:3411 tcp:3411` 후 가상 자료로 보고서 MD·HWPX·PDF와 발표자료 PPTX·PDF를 받았다. 앱 내부 저장소와 `내장 저장공간/Documents/DIANA`에 다섯 파일이 저장됐고, 각 SHA-256이 PC 원본과 일치했다. 서버의 폰 저장 확인과 `download_ready` 상태도 확인했다. 실제 문서 내용이나 실자료는 쓰지 않았다.
- Kordoc 4.24.1: CLI 도움말 실행 성공. Kordoc API로 만든 HWPX를 다시 읽고 표 텍스트를 추출했으며, 문서 인덱스/검색 후보에 등록되는 통합 테스트를 추가했다. OCR은 자동 모델 다운로드를 피하기 위해 끈다.
- 개발 파일: UTF-8 Python·JSON 및 일반 코드·설정 파일의 문서 인덱싱과 별도 수정본 생성 테스트를 추가했다. JSON 원본·수정 결과의 문법 검증을 통과/거부하는 테스트도 포함한다. Python 등 소스 코드는 자동 실행하거나 동작 검증하지 않는다.
- 최신 APK 사본: `앱-설치/DIANA-debug.apk`. 개발용 서명이다. 선택 폴더 복사 설정을 앱과 동기화 엔진이 서로 다른 Android 설정 저장소에서 읽던 문제를 고친 뒤 재빌드·덮어 설치해 확인했다.
- OpenAI: 이번 실기기 수신 확인은 `AI_MODE=lexical`로 수행해 API를 호출하지 않았다. AI가 작성·검토한 실제 결과물은 별도 검증이 필요하다.
- 보고서/PPTX: 가상 문서 `sample-documents/자료-001.txt`로 Markdown 보고서와 6장 편집형 PPTX를 만들었다. 패키지 무결성 검사, 슬라이드 크기·레이아웃·글꼴 정책 검사가 통과했고 경고는 0건이었다. 6장 렌더 미리보기를 눈으로 확인했다. OpenAI AI 작성 결과가 아니며, 실기기 PowerPoint에서 여는 것은 검증하지 않았다. 임시 결과는 `.local/qa-sample-presentation-verified/files/`에 있다.
- 문서 출력 형식: 가상 자료로 Markdown·HWPX·PDF 보고서와 PPTX·PDF 발표자료를 생성했다. HWPX 파싱, PDF 텍스트·페이지 수, 렌더 이미지 레이아웃을 확인했다. 변환 샘플을 갤럭시에 내려받아 내부 저장소와 선택한 Documents 폴더에서 크기와 SHA-256을 다시 확인했다. 샘플 산출물은 `.local/format-qa-v2/files/`에 있으며 GitHub에 올릴 파일 목록에서는 제외한다.
- Android 알림: FCM 자격이 설정되지 않아 WorkManager 15분 주기를 사용한다. 앱에서 백그라운드 자동 확인이 켜진 것을 확인했다. Android 절전 상태에서의 실제 도착 지연은 검증하지 않았다.
- 원격 전원: 이전 구현은 Magic Packet을 `127.0.0.1` 수신기로만 확인했다. 사용자 PC를 실제로 깨우지 않았다. PC MAC, BIOS/UEFI, 공유기 설정은 미확인이다.
- 메일: 기본 연습 모드와 mock만 확인했다. 이 밤사이 작업은 현재 Android 저장만 제공하며 실제 외부 메일은 보내지 않는다.
- 사용 데이터: 이날 로컬 검증은 저장소의 가상 문서만 사용했다. 실제 AI 요청은 선택한 제공자의 API에 원문 발췌를 전송하므로 실행 전 사용자가 계정과 자료 전송을 설정해야 한다.

이날 검증은 로컬 서버와 USB 디버그 역방향 연결을 사용했다. `127.0.0.1` 주소는 PC 내부 또는 USB 디버그 역방향 연결에서만 쓸 수 있다. 이후 실제 Groq 및 외부 HTTPS 검증은 아래 기록에 구분한다.

## 2026-10-23 휴대폰→PC 파일 전송 구현

- 웹과 Android에 파일 하나를 선택하고 확인한 뒤 PC로 보내는 기능을 추가했다. 최대 10MB, 빈 파일·경로·제어문자·Windows 예약 파일명 거부, SHA-256 확인과 전송 번호를 통한 중복 억제를 적용했다. 휴대폰 원본은 유지한다.
- Android는 앱 내부에 전송 준비 사본과 전송 번호를 저장한다. 네트워크 실패나 앱 재시작 후 같은 파일로 명시적으로 재시도할 수 있으며, 서버 응답의 전송 번호·이름·크기·해시가 일치해야 준비 사본을 정리한다. 서버 수신과 PC 저장 완료는 구분해 표시한다.
- 모의 휴대폰이 보낸 80바이트 가상 파일로 실제 로컬 HTTP 업로드·PC 에이전트 수신·크기와 SHA-256 검증·`pc_saved` 응답을 확인했다. PC의 전용 수신 폴더에 저장됐으며 문서 목록과 검색에서도 찾을 수 있었다. 실제 갤럭시에서 새 업로드 UI를 사용한 검증과 구분한다.
- Node.js 전체 회귀 테스트 246개가 통과했다. Android의 파일명·크기·해시·전송 중단 단위 테스트 7개를 추가했으며, 이 기록 시점에는 Android 테스트와 새 APK 빌드를 아직 실행하지 않았다.
- 기존 DIANA 앱으로 새 APK를 받는 비공개 파일 중계 경로를 추가하고 있다. APK 수신과 Android 설치는 별도 동작이며 자동 설치나 추가 설치 권한을 요청하지 않는다. 새 서버 배포·빌드·기존 앱의 APK 수신은 후속 확인 대상이다.
