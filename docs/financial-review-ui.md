# PC 금융 문서 검토 화면

`finance:worker`를 실행하면 Windows 기본 브라우저에 PC 로컬 검토 화면을 연다. 원문·근거·수정 전후·항목별 판단·저장 위치를 나누어 보여주며, 화면에서 최종 승인·거절과 저장본 재검토를 할 수 있다. 앱에서 선택한 작업과 외부 서버 계약, Python 코어, PC 직접 승인 원칙은 유지한다. 아이콘은 기존 `android-app/branding/launcher-source.png`를 그대로 복사한 자산이다.

## 실행

기존 금융 worker 창에 `exit`를 입력해 종료한 뒤 PowerShell에서 실행한다. 학습이나 일반 DIANA 에이전트를 종료할 필요는 없다. 실제 config 경로에는 PC에서 검토한 로컬 설정을 사용한다.

```powershell
cd C:\work\diana
$env:API_BASE_URL = "https://diana-pzw3.onrender.com"
npm.cmd run finance:worker -- --config "C:\work\diana\.local\financial-mobile-demo-b196890e-5cae-4cf0-86c3-aca799885c9e\worker.json"
```

현재 예시 설정은 개발 검증용 가상 자료 3개 작업이다. 브라우저가 자동으로 열리지 않으면 콘솔의 `PC 검토 화면` 주소를 직접 연다. 주소에는 해당 실행의 임시 로컬 화면 키가 있으므로 외부에 공유하지 않는다. 자동 열기만 끄려면 마지막에 `--no-open`, 기존 상세 콘솔만 사용하려면 `--console`을 추가한다.

1. 모바일에서 작업을 요청한다. 현재 실행 세션의 최근 8개 요청이 PC 화면에 표시된다.
2. 수정 전후, 항목별 검토, 원문·근거를 확인한다. 저장 완료와 전체 검토 완료는 별도로 표시한다.
3. 승인 대기 보고가 확인됐고 시간이 남아 있을 때 ‘수정안 승인’을 누른다. 확인창의 작업·형식·요청 ID·미해결 수를 확인하고 ‘승인하고 저장’을 직접 누른다. 거절도 별도 확인창에서 확정한다.
4. 원문·정책·요청 ID·계획·만료·서버 저장 게이트를 기존 worker의 같은 승인 함수에서 재검사한다. 콘솔 명령 입력은 선택 가능한 대체 경로다. `approve 요청ID` / `reject 요청ID` / `cancel 요청ID`도 계속 지원한다.
5. PC 화면의 저장 결과에서 실제 저장·재읽기 여부, 저장 위치, 미해결 항목을 확인한다. 모바일에는 최소 상태만 반영된다.
6. 저장 결과의 ‘저장한 파일 다시 검토’를 누르면 실제 저장 파일을 읽어 현재 원문·지침으로 다시 검토한다. 결과는 별도 ‘저장본 재검토’ 탭에 표시한다. 재검토는 새 파일이나 승인 토큰을 만들지 않고 다른 대기 수정안도 취소하지 않는다. 모바일의 원본 검토 요청 상태를 바꾸지는 않는다.
7. 종료는 PC 콘솔의 `exit`다. 브라우저 탭만 닫으면 worker는 계속 실행되며, worker를 종료하면 로컬 화면 서버도 닫힌다. 재시작은 현재 등록 작업과 일치하는 최근 완료 기록/저장 해시를 확인해 최대 8개 저장본을 불러온다. 이전 승인이나 대기 계획은 복원하지 않는다. 바탕화면 ‘DIANA 금융 검토’ 바로가기로도 실행할 수 있다.

## 로컬 경계

검토 서버는 임시 포트의 `127.0.0.1`에만 바인딩한다. 고정 자산, 세션 키로 보호한 `GET /api/view`, PC 로컬 동작을 처리하는 `POST /api/local-action`을 제공한다. 외부 Render 승인 API, 외부 파일 업로드, 임의 PC 경로 열기, 프로그램 종료 API는 없다. 0.2.0의 별도 PC 등록 경로는 사용자가 고른 파일을 같은 localhost 안에서만 복사한다. Host/Origin/Fetch-Site를 확인하고 CORS를 허용하지 않는다. 상태를 바꾸는 요청은 같은 Origin의 JSON 본문과 임시 세션 키가 모두 필요하다. 외부 스크립트·폰트·분석 도구를 사용하지 않고 페이지 캐시를 막는다. 브라우저 저장소에는 임시 화면 키만 두고 문서 내용은 저장하지 않는다. 임시 키는 최초 URL fragment에서 읽은 뒤 주소 표시줄에서 제거한다.

로컬 동작 본문은 정확히 `requestId, viewId, action`이며 `action`은 approve/reject/recheck다. 파일 경로·문서 내용·계획 해시·승인 토큰은 받지 않는다. `viewId`는 준비된 수정안 또는 검증된 저장 결과마다 새로 생성하는 임시 UUID다. 본문 수신 후 최신 작업/화면 ID/승인 시간/상태를 확인하고, 처리 중 중복 클릭을 막은 뒤 기존 직렬 worker 함수에 연결한다. worker는 별도로 현재 요청/계획/원문/정책/유효 시간/저장 게이트를 확인한다.

저장본 목록은 PC의 고정 `.financial-ledger/request-*.json` 완료 기록 중 현재 등록 작업의 입력 해시와 일치하고 현재 역할로 읽을 수 있는 결과만 사용한다. worker의 마지막 journal도 같은 요청/등록 작업/형식의 LOCAL_SAVE_COMPLETED/saved=true이며 미확인 outbox가 없어야 한다. receipt만 완료이고 실제 worker가 UNCERTAIN으로 끝났거나 ACK 대기인 요청을 자동 완료로 바꾸지 않는다. 출력 경로는 검증된 출력 루트·기록된 계획 해시·허용 형식으로 계산하며 브라우저나 기록의 임의 파일 경로를 따르지 않는다. 저장 파일의 실제 해시·링크/경로·설정/권한을 확인하고, 재검토 전후에도 파일·원문·지침을 확인한다. 불확실하거나 변조된 기록/파일은 목록에서 제외하거나 재검토를 거부하며 덮어쓰지 않는다.

승인 버튼은 현재 개발·사용 테스트용 UI다. `createReviewViewer`의 로컬 명령 콜백과 UI를 기존 실행 검증에서 분리한다. 승인 콜백을 제공하지 않으면 해당 UI 기능을 숨기고 로컬 동작도 거부한다. 추후 버튼을 숨기거나 대체할 수 있으며, 자동 저장 범위와 ‘PC 최종 승인’ 원칙 변경은 별도 결정이다. 모델 학습 완료가 승인 검사를 제거하지는 않는다.

문서와 근거는 `textContent`로 표시해 HTML/스크립트로 실행하지 않는다. 화면 이벤트에는 원문/검토에 필요한 필드만 복사하며 승인 토큰·계획 해시·승인 ID·canonical payload는 넘기지 않는다. 화면이 보유한 객체를 변경해도 실행 계획은 바뀌지 않는다. 동작 검증에 사용하는 가상 자료와 사용자 실제 승인은 구분한다.

이 화면은 PC의 별도 로컬 화면이다. Render 웹사이트와 Android에 문서 내용을 보내거나 새 파일 다운로드 경로를 추가하지 않는다. 로컬 브라우저 확장·관리자·다른 PC 프로그램을 OS 차원에서 통제하는 기능은 아니다. 이번 변경에는 Render 재배포나 APK 재설치가 필요하지 않다. Windows 휴대용 실행기 사용법은 `financial-desktop/README.txt`에 있다. URL로 즉시 체험하는 별도 웹 데모는 후속 작업이다.

## Windows 실행기와 승인·저장 검증 (2026-10-28)

### 자동 연결과 종료 중 등록 차단 (0.2.1)

공통 설정은 문서 검색용 리더와 분리한 설정 전용 리더로 읽는다. AppData 아래의 명시적으로 선택한 설정은 허용하지만, 파일은 16KiB 이하의 일반 UTF-8 JSON이어야 한다. 논리 경로와 실제 경로의 상위 폴더에서 심볼릭 링크·junction을 거부하고, 파일의 링크 수와 읽기 전후 경로·핸들 동일성도 검사한다. Windows가 AppData를 다른 실제 경로로 매핑하는 경우에는 그 실제 대상을 고정한 후 두 경로가 같은 파일을 유지하는지 확인한다. 기존 문서 검색·원문 읽기의 AppData 차단 정책은 변경하지 않는다.

PR #14의 기존 로더에서 AppData 설정 읽기 실패를 재현한 뒤 회귀 검사를 추가했다. AppData 설정 읽기, 비정상 바이트·크기·hardlink·junction 차단, OS 경로 매핑과 대상 변경 차단을 검사한다. 실제 AppData 안의 별도 임시 QA 설정과 새 ZIP의 WorkerSession으로 휴대용 설정 없음 → 공통 설정 선택 → 번들 worker 시작 → localhost 중계 연결 → 정상 종료·잠금 해제를 확인했다. 사용자 공통 설정은 사용하거나 변경하지 않았다.

실행 폴더의 `.local/desktop.json`이 있으면 먼저 사용하고, 없으면 `%LOCALAPPDATA%/DIANA/financial-desktop/desktop.json`의 마지막 연결 설정을 사용한다. 설정을 저장하면 바로 연결하며 다음 실행에도 자동 시작한다. 연결 성공 후 공통 설정에는 파일 경로·서버 주소·화면 열기 설정만 저장하고 연결 키 내용은 복사하지 않는다. 명시적인 `--settings` 실행은 공통 연결 설정을 바꾸지 않는다. 새 PC에서는 최초 설정이 필요하다.

종료를 시작하면 worker에 종료 상태를 먼저 기록한다. 이후 들어온 등록 요청과 아직 commit하지 않은 등록은 `DESKTOP_STOPPING`으로 중단해 잠금 해제 뒤에 등록 파일이 확정되지 않도록 한다. 두 회귀 사례는 수정 전 실패했고 수정 후 전체 Node 검사에 포함한다. 기존 승인·저장 작업의 종료 대기는 유지한다.

### 모바일 금융 상태 갱신 (0.3.8)

첨부 영상에서 상태를 받아올 때 화면 전체를 다시 만들고 스크롤 위치를 비동기로 복원해 한 프레임 동안 맨 위로 튀는 현상을 확인했다. 금융 화면의 shell·ScrollView와 작업 ID별 행을 유지하고 변경된 상태·문구만 갱신한다. 작업 추가·삭제·순서 변경에는 해당 행만 이동하거나 제거한다. 파일 동기화 설정의 변경 알림도 금융 화면을 다시 만들지 않는다. 원문·근거·Diff·결과 파일의 반출 범위는 바꾸지 않는다.

Android JVM 검사 50개와 앱·계측 테스트 APK 빌드를 통과했다. 기존 설치 인증서로 서명한 0.3.8 APK의 서명·정렬·payload 보존을 확인했다. 새 `FinanceUiRefreshTest`는 반복 heartbeat와 상태 변경 시 화면·스크롤·행 재사용, 작업 목록 변경, 무관한 동기화 설정 변경을 검사하며 Android 15 CI 실행에 연결한다. 로컬에서는 계측 APK 빌드까지만 수행했으며 Android 실기기에서 새 APK의 깜빡임 해소를 확인한 결과로 계산하지 않는다.

### PC 문서·작업 등록 (0.2.0)

PC 로컬 검토 화면의 ‘문서 · 작업 등록’에서 UTF-8 TXT/MD/JSON 파일(최대 256KB)을 선택하고 용도·문서 코드·버전을 등록한다. 지침은 기존 id/version/rules 형식 JSON이며 근거 자료 코드와 source_ids를 맞춘다. 선택한 파일은 세션 인증이 있는 localhost로만 전달해 PC의 전용 폴더에 동일 바이트로 복사한다. 원본 파일과 기존 worker/core 설정은 수정하지 않는다. 등록한 사본은 원본 수정에 따라 자동 갱신되지 않으며, 새 코드를 사용한 추가 등록으로 연결한다. 기존 문서/작업의 수정·삭제는 이번 범위에 포함하지 않는다.

작업 화면에서 원문·근거·지침, 보완 항목, 동작·저장 형식을 선택한다. 작업 이름은 모바일에 표시되는 공개 필드임을 화면에 명시한다. 실제 코어의 checklist_review를 PC에서 수행해 정상 검토 결과인지 확인한 후 작업을 활성화한다. 승인·저장 권한이나 검토 의미를 새로 부여하지 않는다. 역할·쓰기 권한·출력 폴더·Python 경로·기존 문서와 작업은 유지하며, 원래 설정의 변경·권한 철회도 계속 확인한다.

등록은 현재 worker의 같은 직렬 큐와 잠금 안에서 처리한다. 검토·승인·저장 중 또는 미확인 상태 보고가 남아 있으면 새 등록을 거부해 기존 수정안을 무효화하지 않는다. 문서 사본과 새 설정은 `<stateDir>.registrations`에 버전별로 배타 생성하고, 검증 후 마지막 commit 표식을 flush한다. 원문/출력/일반 파일 폴더와 겹치는 위치는 생성 전에 거부한다. 미완성 staging은 활성화하지 않고, 기록·사본·해시 변경은 덮어쓰기 없이 차단한다. 같은 revision의 병행 등록은 하나만 반영하며 직전 요청의 동일 재전송은 중복 생성하지 않는다. 쓰기 결과가 불확실하면 추가 등록을 중지한다.

PC 전용 GET /api/local-catalog와 POST /api/local-catalog/documents, /tasks는 기존 로컬 세션·Host·Origin·CSP 경계를 사용한다. 브라우저에서 PC 파일 경로나 설정 경로를 받지 않는다. 기존 Render 금융 register에는 publicTask의 id/label/actions/formats만 보내고 같은 worker ID를 유지하므로, 새 등록 자체가 worker 교체나 90초 재연결 대기를 만들지 않는다. 화면은 ‘PC 등록 완료 · 반영 대기’와 실제 register 확인 후 ‘모바일 작업 목록 반영 완료’를 구분한다. 외부 금융 API와 Android 필드 계약은 그대로라 이 기능에 서버 배포나 APK 재설치는 필요하지 않다. 모바일 금융 모드에서 목록을 새로고침해 확인한다.

기존 콘솔 전용 모드는 그대로이며, 기본 CLI 검토 화면과 Windows 실행기 모두 등록 UI를 지원한다. 검증에는 별도의 가상 파일만 사용한다.

## PR #12 재검토 분류·진단 응답 수정

해시로 확인한 실제 저장 바이트의 공통 문서 메타데이터에서 분류 후보를 읽고, 코어가 전체 envelope·본문/상태 표시·분류를 검증한 정상 검토 결과만 사용한다. 원본 검토서나 현재 근거 설정의 분류로 저장 파일의 분류를 추정하지 않는다. 원본 synthetic/근거 internal로 만든 internal 저장본은 MD/TXT/JSON 모두 재검토할 수 있고, 재시작 후 근거 설정 분류가 달라져도 저장본 분류는 유지한다.

정상 검토는 REVIEW_RESULT, 요청 ID 일치, 정상 상태, 비어 있지 않은 항목, 본문 문자열, 검토 완료 여부와 미해결 목록을 갖추고 기존 계획 무결성 검사도 통과해야 한다. ACTION_REQUIRED 상태만으로 성공 판정하지 않는다. 지침에서 기존 미해결 항목을 제거해 UNRESOLVED_LABEL_REQUIRED로 중단한 경우 원래 코드와 코어 상태를 유지한 실패로 처리한다.

실패한 재검토는 로컬 응답과 화면에서 원인을 표시하며 이전 성공 결과를 대체한다. 항목 0개/빈 본문을 완료 결과로 보이지 않는다. 이미 저장된 파일의 저장 상태는 유지하고 재검토 실패를 별도로 구분한다. 지침을 복구해 다시 검토하면 정상 결과로 돌아갈 수 있다. 이 오류 처리는 PC 전용이며 외부 중계 상태와 문서 내용 반출 범위를 바꾸지 않는다.
