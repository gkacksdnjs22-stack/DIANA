# 디아나 골든 패스 — 시연 시나리오와 영상 콘티

기준일 2026-10-22 · 구현 기간 10/23–10/31 · 제출 영상 권장 길이 3분 30초

## 시연 목표

잠들기 전 사용자가 한 번 맡긴 문서 작업이 PC에서 이어지고, 불확실한 수치가 숨겨지지 않은 검토본과 발표자료가 준비되며, 다음 날 이동 중 모바일에서 빠르게 수정·승인한 뒤 갤럭시에 클린본이 저장되는 흐름을 한 번에 보여준다.

이 시연의 주인공은 AI가 쓴 문장 수가 아니라 **위임 → 근거 확인 → 하이라이트 검토 → 모바일 수정 → 승인 → 저장 확인**이다. 실제 카카오 채널이나 일반 전화망 연결이 준비되지 않으면 대화형 화면은 프로토타입이라고 화면에 표시한다. 워크플로에 없는 실제 발송이나 저장을 영상으로 암시하지 않는다.

## 사전 준비

### 샘플 자료

개인정보가 없는 합성 자료를 쓴다. 촬영 때마다 같은 원본을 사용하고 해시를 기록한다.

| 파일 | 테스트 내용 |
|---|---|
| 2026년 3분기 영업실적 초안.docx 또는 HWPX | 4~6쪽 보고서. 요약, 실적, 원인, 다음 분기 제안 포함 |
| 3분기 매출원장.xlsx | 공식 합계 20억 원. 보고서 초안의 표 한 곳에는 의도적으로 18억 원을 기재 |
| 회의요구사항.pdf | 발표 목적, 청중, 핵심 결론, 발표 시간 5분, 수치 표기 규칙 |
| 출처메모.md | 자료의 출처와 기준일. AI가 채우면 안 되는 추정 항목 1개 지정 |

미리 설계한 불일치는 시연에서 드러나야 할 결함이다. 디아나는 이를 20억이라고 몰래 덮어쓰지 않고 원장과 초안의 차이를 주석으로 표시한다. 발표자료도 동일한 쟁점을 표시한다.

### 위임 조건

전날 밤 사용자는 Android 요청 화면에서 자료 네 개를 선택하고 다음 조건을 입력한다.

- 마감: 다음 날 오전 8시
- 결과: 근거·수치 대조가 표시된 보고서(HWPX·PDF), 10장 안팎의 편집 가능한 PPTX와 열람용 PDF, 변경 요약
- 범위: 선택 폴더만 읽기, 원본 보존, 파일 내 지시문 실행 금지
- 검토 기준: 회의요구사항 충족, 보고서와 슬라이드 수치 일치, 출처 표시
- 충돌 정책: 가능한 작업은 계속하고, 불일치·추정은 노란색 하이라이트와 설명 주석으로 남김
- 전달: Android 저장. 외부 메일은 최종본과 수신인을 휴대폰에서 확인하고 따로 승인한 뒤 발송
- 데모 경로: 실제 AI/API, PC 에이전트, Android 실기기 저장은 연결 상태를 촬영 전 확인. 실패하면 미리 녹화한 대체 흐름을 쓰되 실연결 여부를 자막에 명시

원격 전원은 PC·BIOS·공유기 조합이 사전 검증된 경우에만 본 장면에 넣는다. 그렇지 않으면 PC가 켜져 있고 에이전트가 온라인인 조건에서 파일 처리부터 실제로 시연한다.

## 진행 순서

### 1. 밤에 한 번 맡긴다

사용자는 시작/마감, 샘플 폴더, 산출물, 확인 정책을 확인하고 위임한다. UI에는 “원본 유지”, “충돌은 표시”, “승인 전 발송 없음”이 한눈에 보인다. 작업 등록 ID와 기준 파일 목록을 남긴다.

선택 PC가 꺼져 있고 실제 WoL을 검증했다면 깨우기 요청을 보낸다. 화면에는 신호를 보냈다는 사실과 PC 에이전트가 실제 접속했다는 사실을 따로 표시한다.

### 2. PC가 문서를 읽고 결과를 준비한다

PC 상태가 연결되면 Kordoc 파싱 결과에 HWP/HWPX 여부와 파일명을 보여준다. 보고서 초안·매출원장·요구사항을 비교한다. 타임라인은 파일 읽기 → 요구사항 추출 → 근거 비교 → 보고서 수정 → 제한 횟수 재검토 → PPTX 생성 → 파일 검사 순으로 진행한다.

예상 쟁점은 “보고서에는 18억 원, 매출원장에는 20억 원”이다. 결과의 하이라이트를 누르면 어느 파일의 어느 항목과 충돌하는지 보인다. 출처를 찾지 못한 전망치는 “AI 추정 — 근거자료 없음”이라고 표시한다.

### 3. 이동 중 필요한 결정만 한다

완료 알림을 받은 사용자는 Android에서 요약과 ‘확인 필요 2건’을 본다. 보고서의 18억/20억 충돌을 열어 원장을 근거로 20억으로 바꾸도록 요청한다.

대화 입력 예시: “매출원장 기준으로 3페이지 수치를 20억 원으로 고쳐. 전망치는 추정 표시를 유지하고, 보고서와 발표자료 모두 다시 맞춰줘.”

새 버전 생성 뒤 디아나는 수정된 숫자, 출처, 바뀐 슬라이드와 남은 쟁점을 다시 보여준다. 채팅 화면이 카카오톡 채널에 실제 연결되지 않았다면 상단 또는 영상 자막에 “모바일 대화 프로토타입 · 카카오 채널 연동 전”이라고 표시한다.

음성 UX를 포함할 때는 정차한 상태의 음성 입력으로 수정 요청이나 확인 질문을 보여준다. 자차 전화/SIP 연동이 실제 검증되지 않았다면 통화 연결음·발신 화면을 실제 통화처럼 연출하지 않고, “전화 통화 UX 콘셉트”로 표시한다.

### 4. 마지막 승인과 폰 저장

사용자가 검토본의 잔여 쟁점, 수신인, 메일 제목과 첨부를 확인한다. 명시적 승인 후 디아나는 하이라이트 없는 클린본을 별도 생성하고 승인 기록을 남긴다. 사용자가 요청하지 않은 발송은 하지 않는다.

마지막 화면에서 갤럭시 저장 완료와 SHA-256 검증 상태, 파일명, 수신 상태를 보여준다. SMTP를 실제 외부 테스트 주소로 검증하지 못했다면 “메일 전송 준비” 또는 “연습 모드”라고 표시하고, 실제 전송 완료 자막을 쓰지 않는다.

## 리허설 체크리스트

- 동일한 시드 자료와 예상 충돌을 사용했고 개인 자료가 없다.
- 보고서 원본과 원본 해시가 변경되지 않았다.
- 의도적으로 심은 18억/20억 차이를 노란색 하이라이트와 근거 주석으로 찾았다.
- 자료에 없는 전망을 사실로 쓰지 않았고 추정 표기가 남았다.
- PPTX가 10장 안팎이며 슬라이드와 보고서의 확정 수치가 일치한다.
- 휴대폰 요청이 새 버전을 만들고, 수정 후 확인 사항이 갱신된다.
- 승인 전 외부 발송은 일어나지 않았다.
- 클린본 생성, Android 저장 ACK, 해시 확인을 영상에서 확인했다.
- 실제 WoL·Kakao·전화·SMTP를 검증한 경우에만 실제 동작으로 설명했다.
- 세 번 연속 실행하고 각 실행의 파일·로그·실패를 기록했다.

## 대체 경로와 중단 기준

AI 키나 네트워크가 불안정하면 합성 자료로 사전에 생성한 재현 가능한 실행 로그를 보여주되 “사전 녹화/예시 결과”라고 표시한다. 갤럭시 저장이 실패하면 PC 결과와 실패 상태를 보여주고 폰 저장 성공으로 말하지 않는다. 외부 메일 검증이 되지 않으면 dry-run을 사용한다. WoL이 실패하면 작업 완료처럼 건너뛰지 않고 에이전트 온라인 조건에서 이어가거나 실패 화면을 기록한다.

시연 중 사실 오류나 수신인 오류가 발견되면 발송을 중단하고 검토본을 유지한다. 이 판단은 시연 완주보다 우선한다.
