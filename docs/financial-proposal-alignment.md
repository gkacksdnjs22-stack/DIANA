# KIC 기획안 v6와 금융 모드의 구현 범위 대조

검토 기준은 사용자가 제공한 2026-10-27 기획안 `DIANA-KIC-기획안-v6-최종.pdf` 11쪽이다. 전체 텍스트와 주요 흐름·보안·웹 데모·평가 페이지를 확인했다. PDF는 수정하거나 저장소에 업로드하지 않았다. 다음은 PR #11의 코드/회귀 검증과 기획안의 대응이며, 기획안의 목표를 이미 달성한 결과로 바꾸어 해석하지 않는다.

## 판단

**현재 PR은 기획안의 금융 문서 코어와 PC 승인 흐름을 연결하는 기반 단계에 부합한다. 기획안 전체 MVP가 완성된 상태는 아니다.** 모델 해석·문서 신규 작성·Pyodide 웹 데모·독립 평가와 통신 정책 실증은 별도 작업으로 남는다. Android/Render 경로는 사용자가 별도로 정한 관리용 확장이며 기획안의 브라우저 로컬 데모를 대체하지 않는다.

| 기획안 내용 | 현재 PR의 근거 | 판정 |

| 3·5쪽: 충족 유지, 근거 있는 누락만 보완, 근거 없으면 확인 요청 | ChecklistVerifier/상태 플래너가 SATISFIED·MISSING_WITH_EVIDENCE·MISSING_NO_EVIDENCE·NEEDS_CONFIRMATION을 구분하고 선택 보완을 제한 | 일치. 가상·등록된 표현 범위이며 범용 실사/법률 판단 성능을 의미하지 않음 |

기획안의 `DD-A#p014`는 사례용 출처 예시다. 현재 가상 fixture의 문단 번호가 다르더라도 실제 문서 ID·버전·해시·문단·원문을 동적으로 연결하는 것이 기준이며, 코드를 예시 문단 번호에 하드코딩하지 않는다.

## 이번 추가 리뷰 수정과 기획안의 관계

- 말줄임표의 NFKC 확장으로 새 문장 경계를 만들지 않도록 원문에서 경계를 정한 후 조각을 정규화한다. 소수/전각 숫자 지원은 유지하고 원문 인용은 바꾸지 않는다. 이는 5·6·10쪽의 근거·의미 누락 검사와 잘못된 충족/성공 표시 방지에 해당한다.
- PC_REVIEW_REQUIRED의 상태 ACK만 유실됐을 때 유효한 로컬 계획을 보존하고 같은 보고를 재전송한다. 이후에도 사용자 승인을 새로 입력해야 하며 취소·만료·원문/정책 변경은 계속 무효화한다. 이는 5쪽의 승인 상태·원문 변경 재확인과 장애 처리에 해당한다.
- 잠금 보관의 link/unlink 사이에 멈춘 경우 동일 상태 폴더의 정확한 두 경로·같은 파일·정확한 링크 수·죽은 PID를 확인해 복구를 재개한다. 일반 문서의 hardlink 차단은 완화하지 않고 활성 PID·낯선 링크/보관 파일을 덮어쓰지 않는다. 이는 7·10쪽의 내부 파일 보존과 장애 시 거짓 성공 금지에 해당한다.

## 다음 구현 범위의 구분

1. **현재 연결 기반:** 금융 코어/권한/PC 승인·저장·최소 상태 전달과 재현 가능한 장애 처리를 검증한다. 현재 수행한 범위다.
2. **기획안의 모델·문서 기능:** 금융 전용 작업/인자 계약, 새 문서 작성, 로컬 검색을 설계하고 고정된 학습/검증 절차로 모델과 연결한다. 기존 독립 시험을 보고 학습 개선하지 않는다.
3. **기획안의 공통 데모·정책 실증:** 같은 Python 코어의 Pyodide 웹 데모, 앱/웹 공통 20건, 명시적인 송신 관찰/오프라인 경계, 독립 180+20 평가와 시간 비교를 별도로 수행한다.

기획안을 설명할 때는 “금융 코어와 PC 승인 연결 기반을 구현했고 모델 통합·공통 웹 데모·독립 평가는 후속 단계”라고 구분하는 것이 현재 증거에 맞다. 이 대조는 금융 규정 준수, OS 전체 DLP, 실제 KIC 정책 적합성의 인증이 아니다.
