# PR #11 추가 수정 자체 검토 — 2026-10-27

검토 기준은 `2b1dea21`의 질문 확정 판정, prepare 뒤 조회 장애, 동시 stale-lock 복구 재현이다. 아래는 로컬 코드 재검토와 가상 자료 테스트 결과이며 독립 외부 리뷰나 금융 성능 평가 점수가 아니다.

|---|---|---|
| 확정 진술 | 영문·한국어 등록 긍정, 반복 긍정, 줄바꿈 | 검토서의 등록 진술은 SATISFIED, 원문에만 있으면 MISSING_WITH_EVIDENCE; 원문 인용 유지 |
| 질문·조건·부정 | ASCII/전각/호환/연속 물음표, 질문+긍정, 같은/다음 문장·다음 줄 조건, 부정·미확인·미등록 주변 문장 | NEEDS_CONFIRMATION, review_complete=false; 조건을 잘라 확정하지 않음 |
| 기존 문장 경계 | 소수·전각/호환 숫자·말줄임표 | 기존 회귀 검사 유지; 정규화 전 원문 경계 사용 |
| 통신 진입·준비 | register/next/observe 각각 요청 전 장애·서버 처리 후 응답 유실; observe 연속 실패 | 복구 후 명시적 준비 마무리, prepare 1회; 수동 테스트 승인 후 저장 1회, 후속 큐 진행 |

| 상태 보고 | 검토 ACK 유실·취소, 저장 시작 ACK 유실, 완료 ACK 유실 및 서버 재시작 | 유효한 검토 계획만 유지, 게이트 모호 시 UNCERTAIN, 완료 보고 재시도는 중복 실행 없음 |
| 동시 stale 복구 | 두 실제 자식 프로세스를 기존 파일 삭제 직전에 지연 | 기존 버전은 두 획득 재현; 수정 버전은 조정 잠금 소유자 한 개만 획득 |
| 동시 시작·프로세스 종료 | 6개 프로세스 동시 시작, lease 해제 없이 자식 종료 후 재시작 | 소유자 한 개; 프로세스 종료 후 OS 잠금 해제 및 기존 메타데이터 보존 |

문장 판정은 선택된 근거 문단의 미등록 주변 문장도 추가 확인으로 처리하도록 강화했다. 이에 따라 기존 CRLF 인용 시험의 “등록 긍정+관련 없는 줄”은 “등록 긍정 자체가 CRLF로 줄바꿈”된 자료로 변경했고, 주변 미등록 조건을 버리지 않는 동작은 별도 행렬에서 검사한다. 동작을 숨기기 위한 기대값 완화가 아니라 명시적인 보수화이며 일반 문장 해석 기능을 주장하지 않는다.

새 SQLite 조정 파일의 최초 생성 중 중단이나 불확실한 파일은 자동 교체하지 않는다. 현재 프로토콜을 사용하는 로컬 worker를 대상으로 검사했으며 구버전 혼용·외부 프로그램의 파일 변조·네트워크 파일시스템까지 검증한 것은 아니다. 재시작은 이전 승인을 복원하거나 요청을 자동 실행하지 않는다.

전체 검사 수치와 실행 범위는 [검증 결과](financial-mobile-verification.md)를 따른다. 학습·모델·독립 평가·Android 실기기 검증·운영 서버 배포는 이번 수정 범위에 없다.
