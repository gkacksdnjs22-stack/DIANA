# Android 내부 기능과 연결하는 방법

## 제품 결정

목표는 사용자가 앱을 계속 열고 지켜보는 경험이 아니라, 자기 전에 맡긴 결과물이 아침에 휴대폰에 준비되어 있는 경험이다. 최초 한 번 Android 연결 앱을 설치·등록하고 저장 위치와 알림을 설정한다. 이후 작업은 PC/서버에서 이어가고, 폰에는 결과를 자동 동기화한다.

일반 앱이 상용 갤럭시의 운영체제 자체에 새 시스템 기능을 심는 것은 별개다. 특권 시스템 앱은 시스템 이미지와 제조사 권한 구성에 관계된다. 공모전은 일반 Android 앱이 제공할 수 있는 빠른 설정 타일·알림·문서 저장 연동으로 구현한다. 루팅이나 시스템 이미지 변경을 전제로 하지 않는다.

## 사용자 경험

1. 최초 연결은 앱에서 설정한다. 새 업무 위임은 홈 화면 바로가기에서 시작하고, 빠른 설정 패널의 ‘DIANA’ 버튼은 PC 연결이나 미리 등록한 반복 작업의 시작·일시중지에 사용한다. 타일은 앱 전체를 여는 용도보다 반복 동작에 맞춰 구성한다.
2. 자기 전에 원본 문서·수정 목표·검토 기준·완료 기한·전달 위치를 지정한다.
3. 폰 화면을 꺼도 서버가 작업을 보관하고 PC를 깨운다. AI 작업은 폰이 계속 켜져 있어야 실행되는 구조로 두지 않는다.
4. 완료 파일을 서버에 등록하고 푸시로 결과가 준비됐다는 알림을 보낸다. 푸시에는 파일 원문이나 계정 비밀값을 넣지 않는다.
5. 앱의 WorkManager 작업이 인증된 API에서 파일을 다운로드하고 SHA-256을 확인한다.
6. 앱 내부 결과 보관함 또는 사용자가 처음 선택한 문서 폴더에 저장하고, 저장 성공 응답을 서버에 보낸다.
7. 서버는 ‘생성 완료’, ‘전달 준비’, ‘폰 저장 확인’을 구분한다. 다음 날 알림을 누르면 이미 받은 HWPX·PDF 보고서와 PPTX·PDF 발표자료를 연다.

## 기술 구성

- Android 앱: Java 네이티브 앱. 6자리 일회용 페어링, Android Keystore에 암호화한 토큰, 작업 목록·결과 보관함, 직접 동기화, 파일 열기/공유, 선택한 문서 폴더 복사.
- 백그라운드: WorkManager 15분 주기와 FCM 토큰 수신 경로를 앱에 준비했다. 현재 서버에는 Firebase 프로젝트/서비스 자격이 없어 FCM 푸시는 비활성이다. 앱은 주기 동기화를 사용한다.
- 저장: 첫 버전은 앱 내부 파일 보관함. 사용자가 일반 파일 앱에서도 접근하길 원하면 Storage Access Framework로 전용 폴더를 한 번 선택하고 해당 URI 권한을 유지한다. 운영체제가 허용하지 않는 전체 저장소 접근을 요구하지 않는다.
- 진척/완료: 서버 작업 상태와 `artifact SHA-256`·앱의 수신 확인으로 구분한다. 서버 파일 생성만으로 ‘폰에 저장됨’이라고 표시하지 않는다.
- 재연결: 네트워크가 복구되면 누락된 완료 작업 목록과 해시를 대조하여 이어받는다. 파일 작성 도중 끊기면 미완료 파일을 완료본으로 표시하지 않는다.

FCM과 WorkManager는 휴대폰 전원·네트워크·OS 절전 정책에 영향을 받는다. 특정 시각에 휴대폰 저장이 무조건 끝난다고 보장할 수는 없다. 서버에서는 파일 준비 마감과 실제 수신 확인을 별도로 관리하고, 충분한 전송 여유 시간을 둔다. 앱을 열 때도 누락된 결과를 즉시 동기화한다.

## 현재 구현과 다음 연결 작업

제어 서버와 Android 앱 코드는 구현했고 개발용 APK를 빌드했다. 페어링은 웹 화면에서 만든 6자리 코드로 한 번 연결한다. 앱은 기기 전용 Android Keystore에 토큰을 암호화해 저장한다. 결과는 앱 내부 저장소에 원자적으로 다운로드하고 SHA-256/크기를 다시 확인한 뒤 서버에 수신 응답을 보낸다. 사용자가 문서 폴더를 골랐으면 외부 폴더에도 복사·검증한다. 백그라운드 동기화는 최대 15분 간격이며 OS 절전이 실제 간격을 늘릴 수 있다.

현재 빌드: `../앱-설치/DIANA-debug.apk` (개발용 서명). 갤럭시 SM-S711N에서 ADB `device` 승인, 앱 설치·실행, 6자리 페어링을 확인했다. 변환 샘플 보고서 MD·HWPX·PDF와 발표자료 PPTX·PDF가 앱 내부 저장소 및 사용자가 고른 `Documents/DIANA`에 저장됐고, 다섯 파일의 SHA-256이 PC 원본과 일치하는 것과 서버 수신 ACK를 확인했다. 선택 폴더 경로가 동기화 엔진에서 누락되던 설정 저장소 불일치도 수정했다. 실제 AI가 생성한 결과물은 별도 검증이 필요하다. 실제 인터넷 사용은 로컬 주소가 아닌 HTTPS 제어 서버가 필요하다. FCM 발송 서버, 빠른 설정 타일, 휴대폰→PC 업로드 기능은 아직 연결하지 않았다.
